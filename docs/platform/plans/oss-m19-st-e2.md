Both example configurations run against their own real PostgreSQL installation
and browser. Required acquisition witnesses are address choice, explicit consent,
success, same-command replay, duplicate contact, both quotas, unchecked consent,
unknown choice and raw registry-field refusal. Apply the seed twice and refuse an
intentionally conflicting registry row loudly with transaction rollback. Read the
durable case through the native acquisition list port under an activated human
operator actor in the test harness only. Fixtures use native account and operator
writers, never fabricated business rows. Preserve the required purchase browser
test unchanged; an absent purchase binding is not purchase acceptance.

The smallest adequate implementation is one host action, one owned typed registry
and the existing install transaction, without a new service or framework.
Admission and payload validation precede the native call. Public success/replay
exposes only the case reference. The insert names its columns, is keyed by
source/reference/revision and verifies provenance and active state after insertion;
a mismatching existing row fails the entire installation transaction.

projections, hidden registry conflicts and overstated purchase coverage. Exact
payload admission, server-owned tuple selection, the existing requester identity,
a minimal public receipt and post-insert verification discriminate those boundaries.

Run neutrality, source/extracted checks, strict typecheck/build, structural scan,
publication policy/typecheck, lint, affected importer tests, real Docker/browser
witnesses and real package comparison with exact main. Heavy stages use focused
admission. Maintain publication and ownership inventories and regenerate navigation.
Scan all refs before snapshots and record every code-path hash against the accepted
WIP. Finish prose before committing and preparing native review; keep final
integration, pack and review evidence outside the tracked tree after that point.
