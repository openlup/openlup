## Composition and recovery contract

Guest checkout resolves a contact only after bounded input and requester-quota
admission. Signed-in checkout derives its client from the native session. Guest
profile refresh is limited to unlinked contacts. The contact factory's clientId,
linked and created facts stay internal. Public success has the same shape and
configured response floor for new, unlinked and linked email addresses; storage
and network tails are variable. Contact persistence and order creation are
separate transactions. The host owns retention of unpurchased contacts.

An admitted new order receives a generated 256-bit recovery token through the
native PostgreSQL token port and a host-composed captured recovery message.
PostgreSQL stores only the SHA-256 hash and fixes expiry at order creation plus
24 hours. This is a database rule, not an adopter-configurable lifetime.
One live link per order: a new link ends the previous link of the same order.
The service capability belongs only to the host's admitted-order producer;
an email or arbitrary order ID never grants issuance for an existing order.

The raw token appears only in the creating response and the separate private
checkout-recovery mailbox. That mailbox is not an authentication challenge stream,
log, receipt or event. Its directory is 0700 and its file 0600. Subject, body and
expiry/order labels are typed owned configuration; expiry displays the native
instant. No real outbound delivery is claimed.

Completion reads the query token once, synchronously removes it with history
replacement before bootstrap requests/render, and never copies it to links,
title, sign-in return paths or errors. Requests carry it in their body. Memory
and sessionStorage preserve reload convenience, not authority. Native inspection
precedes rendering: active/pending permits sandbox controls, consumed/paid shows
confirmation only, and expired/cancelled/unavailable states refuse distinctly in
both locales. Guest payment validates the token's exact order; signed-in buyers
retain native-session ownership. Inspection preserves declared subscription
mode and cadence. Hash lookup makes no constant-time PostgreSQL claim. No RAM
credential store or direct recovery-settlement shortcut remains.

## Preserved boundaries and exclusions

The interim quota retains bounded process memory, hash-only attempt facts, exact
replay before email/requester quotas, no count on denial and fail-closed behavior.
Restart resets it. Its existing decision callback is the replacement seam.
The single interim price function resolves configured per-unit subscription
prices before quantity; seeded mode prices match, discounts are empty and there
is no promotion identifier. First-subscription acquisition remains a later row.
Zero initial and renewal shipping remain separate interim limits. Their future
restore values remain owned configuration; this contribution adds no charge.

Protected server, origin and session source and the required browser spec remain
byte-identical to the base. No package implementation, SQL, grants, control or
workflow is changed by the application's own delta. Generic subscription commands,
broader payment/operator repair, invoice/returns/OMS mutations, shipping/tracking,
bundle purchase, research/ingest ownership and hosted qualification remain outside
this row. Never pause/freeze an active subscription, confirm an undelivered
replacement, move its cycle earlier or stack delivery extensions.

## Local commit continuation and canonical UUID matching

The maintainer authorized the accepted composition as one local signed commit,
followed by the bounded canonical UUID repair as its own named signed commit.
Focused local proof belongs to this continuation. Review and delivery retain
their assigned train slot.

therefore validate and compare the canonical UUID value while preserving the
request and existing response identifiers. Real PostgreSQL host cases cover guest
and native signed-in reads and sandbox payment, lowercase equivalence and the
existing non-UUID refusals in both configurations. The initial regression run
exposes the two spelling-sensitive comparisons before their repair.

Self-retro. The case-insensitive validator and byte-sensitive identity comparison
had different acceptance rules. Canonicalizing only the validated comparison
operand repairs that mismatch at the two affected boundaries.

HTTP requests. This keeps the starter host under its own strict compiler profile
and exercises native authentication, origin admission and payment composition
without importing the entire host graph into the root tests' compiler profile.
A clean install, package build and public typecheck of the accepted composition
passes; the earlier compiler error arose only from that test import graph.
