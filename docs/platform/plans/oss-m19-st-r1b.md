## Composition and recovery contract

Guest checkout resolves a contact only after bounded input and requester-quota
admission. Signed-in checkout derives its client from the native session. Guest
profile refresh is limited to unlinked contacts. The contact factory's clientId,
linked and created facts stay internal. Public success has the same shape and
configured response floor for new, unlinked and linked email addresses; storage
and network tails are variable. Contact persistence and order creation are
separate transactions. The host owns retention of unpurchased contacts.

An admitted new order receives a generated 256-bit recovery token through the
native PostgreSQL token port and a host-composed captured recovery message.
PostgreSQL stores only the SHA-256 hash and fixes expiry at order creation plus
24 hours. This is a database rule, not an adopter-configurable lifetime.
Checkout links coexist until expiry or payment; issuing another does not revoke
the earlier link. Pending renewal-cycle orders refuse checkout issuance.
The service capability belongs only to the host's admitted-order producer;
an email or arbitrary order ID never grants issuance for an existing order.

The raw token appears only in the creating response and the separate private
checkout-recovery mailbox. That mailbox is not an authentication challenge stream,
log, receipt or event. Its directory is 0700 and its file 0600. Subject, body and
expiry/order labels are typed owned configuration; expiry displays the native
instant. No real outbound delivery is claimed.

Completion reads the query token once, synchronously removes it with history
replacement before bootstrap requests/render, and never copies it to links,
title, sign-in return paths or errors. Requests carry it in their body. Memory
and sessionStorage preserve reload convenience, not authority. Native inspection
precedes rendering: active/pending permits sandbox controls, consumed/paid shows
confirmation only, and expired/cancelled/unavailable states refuse distinctly in
both locales. Guest payment validates the token's exact order; signed-in buyers
retain native-session ownership. Inspection preserves declared subscription
mode and cadence. Hash lookup makes no constant-time PostgreSQL claim. No RAM
credential store or direct recovery-settlement shortcut remains.

## Staged guest admission repair

The maintainer authorized one bounded repair for the account-state admission and
changed-identity replay findings. This continuation is staged for the maintainer's
security read; it authorizes no commit, review, push or delivery action.

Guest admission has no linked-contact option or branch. New, unlinked and linked
contacts receive the same public result shape and configured response floor.
The registrar alone decides whether an unlinked profile can be refreshed; its
account and client facts remain internal to the host.

After quota admission and before registration, one synchronous host section binds
the command key to a digest of the normalized e-mail and requester fingerprint.
A changed identity receives the existing admission refusal. The binding also
applies with a permissive replacement callback. The existing retention and capacity values bound this process-local map;
expired entries are dropped and full capacity refuses. There is no new service,
package, SQL, public callback contract or persistence authority.

The regression extends the existing real-HTTP PostgreSQL host suite: all three
contact states, retained-key changes beyond the quota, exact replay, concurrent
distinct identities, and a permissive callback. Contact counts and registration
calls discriminate the two mechanisms. Both configurations pass the new cases
in the default zone and both offset zones. Disabling the binding in scratch
creates five extra contacts and fails all four replay cases; restoring the
linked-contact denial fails both three-state cases. Every new heavy case has an
explicit 30-second bound above four times its measured local duration.
The existing standalone limiter's changed-input characterization remains intact.

Self-retro: isolated quota tests did not establish admission before independently
committed contact writes. The repair proof observes that composed boundary and
removes the account-dependent branch instead of adding another policy choice.
