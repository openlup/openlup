## Evidence and current blockers

- Existing outbox, renewal and prepared-payment claims are local database fences;
  a restored database can duplicate them. The HTTP payment client caches OAuth
  bearer tokens, so rotating an OAuth client secret alone need not revoke a
  previously admitted request.
- Managed customers link through `clients.auth_user_id`; native customers use
  `clients.principal_id`. Direct OIDC derives a UUID from the exact issuer and
  subject. Those identities need explicit binding, not email inference.
- The ordinary blob port has no byte read, version, metadata or ACL contract.
  Its S3 and managed lists are not complete authenticated transfer inventories.
- Canonical client insertion invokes
  `customer_subject_capture_lifecycle_trigger` in
  `20260815130000_customer_recovery_console.sql`, fabricating an additional
  lifecycle event. Cycle insertion invokes
  `subscription_delivery_alignment_guard_cycle_insert` in
  `20261022090000_fulfillment_delivery_alignment.sql`, which can consume admission
  or settle alignment. Order/item sum constraints are also user INSERT triggers.
  The first transport refuses **every** enabled user INSERT trigger, without a
  name-based exception, trigger disabling or replication-role changes.
