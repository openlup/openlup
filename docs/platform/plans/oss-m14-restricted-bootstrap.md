# M14 restricted PostgreSQL bootstrap

Status: development-preview task, open. Audience: contributors preparing a fresh
PostgreSQL 16 installation. This task is a bounded part of M14; it does not
close M14 or qualify a hosted provider.
The 91-unit qualified source is later than the published 0.30.0 package set;
this page grants no installation support for that release.

## Outcome and authority

Install the current 91-unit portable catalogue with an actual non-superuser
migration login in either installer-managed or operator-provisioned role mode.
The accountable maintainer has authorized local implementation, signed commits,
submission and merge after the required reads, review and gates. Credentials,
release dispatch, deployment, settings and production remain separate owner
actions. The active supervisor is the sole writer for this task.

The migration login is a **trusted administrator**. It retains ADMIN membership
in protected groups and can deliberately reacquire owner execution. A removed
temporary SET edge does not isolate the database from that login. Runtime and
restore logins remain restricted nonowners.

## Boundaries and acceptance

The new `qualified-admin` generation replaces exactly five installation units:
baseline, actor authentication, acquisition foundation, runtime capabilities
and retained import. It shares every other current unit, including the issued
runtime-completion tail at position 90. Legacy 88 and the existing qualified
generation keep their issued files, hashes, ledger prefixes and inventories.
There is no conversion of an installed ledger to this fresh generation.

Admission must observe the real migration session, database ownership, held
lock, canonical visibility, PostgreSQL 16, exact prefix and protected membership
graph before normalizing declared principal names. Installer-managed mode may
create its six fixed groups; operator-provisioned mode uses preprovisioned
groups and declared grantors without requiring CREATEROLE on the migration
login. Both need independently frozen role-mode inventories. Neither may turn
an observed target digest into its own expectation.

Local completion needs actual 91-unit apply, status, replay, interrupted-prefix
resume, final ownership and privilege sealing, runtime and restore operations
and refusals under their own logins. Production connection consumers must bind
runtime, direct migration, optional read-only and dedicated scheduler sessions;
transaction pooling must refuse for session advisory locks. Reuse the existing
package executor, per-unit transaction, session hook and final inventory check.

Connected restore for this generation, hosted qualification, pooling recipes,
release and activation are outside this task. Whole M14 remains open with its
other transfer, recovery and adoption obligations.

## Delivery checkpoints

1. Reader preparation: accept only the fixed future identities and manifest
   shape, retain six current approval rows, and keep the five proposed files
   inert. No new active SQL or selection is admitted at this checkpoint.
2. A separate exact-byte approval adds all five identities after the reader
   lands. Issued approvals cannot be repinned.
3. Active SQL and the explicit 91-unit generation follow the landed approval.
   Qualify both role modes and actual connection consumers before claiming the
   local outcome. Sensitive API and security-control changes require a
   stabilized maintainer read before DCO sign-off.

The smallest adequate implementation extends the finite manifest reader and
existing runner. A second installer, generic role compiler or approval store
adds no required capability. Use existing policy, inventory, neutrality,
admission and affected PostgreSQL witnesses before the broad local gate; then
obtain two independent full native reviews and complete required verification.

Checkpoint self-retro: retaining the issued runtime-completion tail removes an
obsolete extra unit and keeps both selected catalogues at 91 units. The exact
future identities stay inert until their separate approval and introduction.
