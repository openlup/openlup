# M14 recipe conformance runner

Status: implementation in progress; development-preview proof only.

## Outcome and boundary

One executable runner composes the existing restricted two-mode installation,
connection and released-schema witnesses for an explicitly disposable self-host
PostgreSQL 16 target. External owner-only credential files never enter source or
receipts. Structured receipts identify exact inputs and retain explicit pending
sections for transfer (8D), recovery (9A), OIDC (10I), S3 (10O), hosts and effort
(10H/10S). Neon and RDS remain pending actual hosted admission and endpoints.
No provider registry, coordinator, business-provider branch, release, deployment
or changes to installation/transfer/object adapters are in scope.

## Acceptance, risk and sufficient proof

Reuse the existing proof bodies with explicit target inputs, keeping their
ordinary disposable-fixture execution. Each mode and the legacy upgrade must
use a separate fresh installation. Verify TLS, real identities/roles, request,
direct/read/session paths, lock contention and switched-backend refusal. Require
actual previous application code for the conformance receipt; its optional
ordinary test path cannot count as rollback proof. Record exact source/package
and image identities, versions, timestamps, declared limits and section outcomes.
Prove missing/undeclared target and unsafe credential-file mode refuse before
connection, and credential-bearing failures cannot escape into receipts/output.
Execute a local PG16 receipt plus focused refusal/process proof. Run cheap
policy/inventory/neutrality/structural/secret checks, then load-gated affected
proof and lint. Obtain two fresh full reviews and canonical verification after
the required read. No passing unit or local receipt establishes hosted coverage.

The primary risks are destructive reuse of a non-disposable database, secret
leakage through child output, and a receipt attributing local fixtures to a
selected external target. Bind all witnesses to the declared target, suppress
raw errors, check freshness before writes and report unsupported targets pending.
Simplicity pre-check: parameterize existing witnesses and compose their evidence;
a second installer, arbitrary shell commands or pluggable provider registry is
unnecessary.
