The [G9 outcome](oss-m19-g9.md#outcome-scope-and-authority) explicitly supplies
owned account invoice history and artifact reads and states that starter route
composition remains with its host. The
[PostgreSQL entry](../../../packages/platform/src/invoicing/postgres/index.ts)
exports `createPostgresInvoiceAccountHistory` and
`createCapturedPostgresInvoiceProvider`; the latter returns both `provider` and
`artifacts`, including captured PDF download. These are natives already on main,
not missing native history or storage APIs.

[`createInvoiceAccess`](../../../packages/platform/src/account-support/invoiceAccess.ts)
accepts `accountHistory` (`read` and `resolveDownload`) and `artifacts`
(`download`). History requires the former; download requires both. It verifies
that the history's account/order match and the document is a member before
resolving a ticket. The native history's `accountRef` is the authenticated
principal UUID, never a browser claim or a client UUID. The host must supply its
runtime executor, select the captured provider explicitly, bind that verified
principal/order/document context and map the route response. Operator reads
add the server-side authorization callback and selected provider/duty readback;
account ownership checks are not replaced with a browser-supplied operator ID.
See the [read-model ordering](../../../packages/platform/src/invoicing/readModel.ts)
and [G9 source check](oss-m19-g9.md#source-check-and-implementation). Neither invoice
route is mounted or newly qualified in r1a.

an explicit `node:http` request to `127.0.0.1:4319`, with the configured canonical

unconfigured case retains Compose's original probe. No origin, session or native
binding policy changes are included.
