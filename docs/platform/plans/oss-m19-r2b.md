# Starter scheduled renewal, account facts and notices

Status: historical record, 2026-11-06.

Historical implementation checkpoint; the current task record is
[PR #546](https://github.com/openlup/openlup/pull/546). Joined recovery now passes
on the completed native installation; earlier checkpoint observations below are
not current delivery instructions.
Development preview only.

Outcome: compose the existing native renewal and retry owners into one scheduled
sandbox job, project owned payment and delivery facts, and render transactional
notices into the private captured transport. Values belong to typed application
configuration. The same unpaid obligation and frozen money survive restart.

Scope: starter host modules, typed configuration, neutral English/Polish copy,
focused source and real-PostgreSQL witnesses, and additive composition hooks.
No package code, SQL, npm entry, provider, control or release change. Recovery
authorization and private artifact persistence have a separate host owner. Consent
and signed opt-out await their native consent/purpose support; shipment and
invoice joins await their existing owners. Reminder policy, historical closure,
winback and escalation retain their named interim limits in subscription care.
No full reference-adopter notice parity or real-provider claim.

Authority: local build, proof and unsigned WIP checkpoint only; no DCO, native
review, submission, push, PR, publication or production action. Worktree
`oss-m19-r2b`, branch `codex/oss-m19-r2b`; shared base
`5cabc00d4b84121c16ed15c641735fb50e92717f`. Policy revision is separately pinned
to `2245d037d55dbe4e324e630da851402d9efccd1c`.

Acceptance: disabled/unready jobs never claim; all executors share the durable
population lease; one service invocation reports actual checked, updated, failed
and deferred outcomes. Initial attempts use the sandbox renewal rail; retries
use persisted simulator observations and exact payment-owner readback. Account
facts distinguish charge dates from arrival and effective address outcomes.
Notice issuance preserves one private artifact, token identity and frozen expiry
across retry; opaque delivery references never contain bearer material.

Proof plan: cheap contract/type/structural checks before broader tests; real
PostgreSQL under both owned configurations, restart/replay/ambiguity/late truth,
late-delivery maximum/no-stacking and undelivered-replacement refusal. Preserve
`browser/journey.spec.ts` byte for byte. Run scanner, lint, dist-export,
neutrality, strict starter build and both browser profiles before any later
review. Report inherited failures separately without repairing other owners.
Heavy stages and containers use the prescribed focused admission gate.

Risk: issuance and capture cannot share a transport transaction; readback must
refuse unknown or missing identity instead of generating a replacement credential.
Simplicity pre-check: reuse the native service, job ledger, simulator, account
sources and transactional receipt owner; add no daemon, bearer ledger, rich
account assembler or second notice producer.

including two configurations, competing population executors, actual child-process
