## Current evidence and design choice

The merged MVP at this base supplies an offline, version-bound installed locator. Its three-arm complex dogfood passed 10/10 for direct, context and adaptive approaches in one run each; it did not show a speed or quality advantage. This checkout has 210 Git-tracked Markdown files, about 7.36 MB and 3,108 headings; the existing `markdownHeadings` parser scans them in about 65 ms on this host. `documentationCandidatePaths` includes untracked files and is therefore unsuitable as a search inventory. `markdownHeadings` gives parent headings spans that contain descendants, so a locator must use the *next heading of any level* to make disjoint section text. `docs/platform/plans/**` is history, and `Status:` prose alone does not establish currentness. `docs/platform/SOURCE_MAP.md` and generated `AGENT_CONTEXT.md` are projections, not canonical implementation truth.

`.agent-protocol.yml` names a template, generator and validator absent from this checkout. The repository's `early-package-gates.md` explicitly records use of `docs/platform/plans/` without a native Plan Protocol pass. This plan uses that convention; no validator pass is claimed. The smallest alternative is the paired AGENTS routing card plus direct `rg` and `SOURCE_MAP.md`. A locator is kept only if the bounded comparison below shows a distinct navigation or source-quality benefit on complex tasks.

## Agent decision rule

| Missing evidence | First route | Escalation and stop condition |
| --- | --- | --- |
| Exact path, exported symbol or error text | Open the path or use scoped `rg` | Read implementation and nearest tests; stop when the contract and failure boundary are known. |
| Unknown documentation owner or cross-domain topic in a repository checkout | `SOURCE_MAP.md`, `config/doc-routing.json`, then scoped `rg` over Markdown when the owner is still unclear | Open owner pages, then source, callers, tests and migrations for each affected boundary. |
| Architecture, migration, replay or compatibility change | Trace owners, call sites, invariants, migration order and tests | Compare all changed module boundaries; a search hit is a lead, not implementation proof. |
| Installed adopter application | Its own instructions and the *installed* version's `openlup-context` and package files | Refuse checkout documentation from another version as an installed contract. |
| Old decision or proposal | Explicit historical search | Label it historical and verify its claims against current owners/code. |

No result is evidence that an API or seam does not exist. Agents may translate freeform Polish intent into concise repository terms before searching. Direct reading remains the default for known paths; no new locator is required for the retained route.

## Acceptance and refusal boundaries

The locator-specific checks below were go/no-go criteria for the spike; the retained implementation is the paired route card.

- The guide chooses routes by task evidence without an extra classifier; known-path work remains one direct open or scoped search.
- Repository results use only tracked, materialized Markdown and current bytes. Each citation opens an exact path and line range in this checkout; nested sections do not repeat the same body text in multiple hits.
- Default results cannot rank a historical plan, changelog history, generated projection or instruction file as a current platform contract. Explicit wider search labels them. Other pages may still be candidates or local examples; path role alone never grants contract authority.
- Repository search never pretends to describe an installed npm version. The installed route remains version matched and offline.
- On fixed cases, there are zero wrong-version/currentness claims, zero unopenable citations and zero critical invariant omissions. The predeclared complex-task threshold decides whether the locator remains recommended.
- Full native review, clean committed verification and any delivery are outside the local-only authority of this task. Mandatory failures must be diagnosed and reported, not silently waived.

## Risks and replan triggers

The likely bottlenecks are ranking related sections without flooding top results, stale plans crowding canonical guidance, and false certainty from lexical misses. Keep disjoint sections and explicit roles; use direct code tracing for invariants. Query-time parsing avoids cache invalidation at this corpus size. If the command requires a new dependency, persistent state, package-budget change, or material runtime abstraction, stop that expansion and return to direct search. If the comparison shows no distinct benefit, remove the locator and document the result; do not add vector or graph search to rescue it.
