# Bounded notice-table admission

## Outcome and scope

Stage one checker-pinned allowance for the native paid-notice forward to create
`public.subscription_notice_refusals` and give the runtime only SELECT/INSERT.
The reader accepts exact guarded grant and policy statements after same-file
creation. Existing revokes, RLS narrowing and all issued identity fences remain
unchanged. The independent PostgreSQL comparator checks the resulting ACL, RLS
and policy. All other new relations remain owner-only.

This control changes the reader, its witnesses, the G8 class entry and the owning
migration documentation. It changes no feature migration, bound forward pin,
public package API, package budget, review machinery or qualified-installation
admission. The separate qualified-completion predecessor remains separate.

## Risk and execution

The risk is accidentally widening a repository-wide admission boundary. Use a
row-scoped constant and direct byte equality rather than a general ACL grammar.
The PostgreSQL comparator remains independent of those string constants and
checks the actual catalog. Scratch source and exports stay outside the worktree.
Freeze the completed tracked inputs before the final checks and coordinator read.
