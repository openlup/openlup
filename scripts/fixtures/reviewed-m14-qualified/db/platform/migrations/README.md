# Qualified installation approval fixtures

The five issued inert files retain the exact whole bytes bound in
[`qualifiedInstallations`](../../../../../../config/reviewed-platform-forwards.json).
The sixth runtime-completion fixture is an unapproved proposal retained with
reader preparation; its integrity assertion is not an active approval pin.
They are not an installation chain, a package SQL export or a migration source.
Reader preparation preserves the exact five-row approval registry and the
canonical schema-2 manifest's legacy 88-unit and restore-bound qualified 90-unit
selections. Trusted admission parses a changed registry using main's reader
before its no-SQL return. The reader support must therefore land first; a later
pin-only change may append the exact sixth approval. Only after that approval
lands may the SQL feature introduce the exact file and append its selected row.
Observed installation hashes cannot replace prior source approval.

The [migration owner](../../../../../../docs/platform/DATA_AND_MIGRATIONS.md#module-catalogues-and-installed-histories)
explains generation selection and ledger identity. These fixtures do not prove
installation, runtime completeness, managed-host qualification or activation.
