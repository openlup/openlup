Adds experimental declared SKU successors, authoritative withdrawal impact,
explicit successor proposals and accepted unpaid stock-wait resolution for the
next 1.x release. Publication authoring version 5 retains immutable pair
provenance in manifest version 4; existing authoring, receipts and readers keep
their original dialects. An offer never changes an agreement during renewal.

Migration: install the complete native chain, including the successor paid-fact
producer, before using version 2 generation stores. Keep the legacy readers for
legacy operations and cases; select new cases by explicit `legacy|successor`
kind. Original operation arbiters, schedule keys, composites, projection bodies,
terminal receipts and recovery snapshots remain intact. New generations retain
the original anchor and use separate execution identities and native graph links.
No backfill or automatic migration of a frozen basket runs.

Deploy the opened-event dispatch bindings and M04 templates before installing
the forward's opened-event producer hooks. Both opened events and publication
events invoke the same transactional notice writer. Commit source claims before
commerce work; acknowledge after committed handoff or authoritative obsolescence.
Keep retryable recipient, lineage and delivery failures visible. Roll forward
after accepting a proposal; issued SQL and historical receipts are retained.

All bindings remain unbound. Installing exports or SQL enables no worker,
capability, provider transport or payment retry. A host must qualify its native
generation-aware payment, retry, fulfillment, transfer and notice composition
before enabling it. Unsupported generation retry bindings refuse activation;
root-only retry stores cannot accept a successor UUID.

Managed divergence design: a managed twin needs `catalog_sku_successors`, the
four successor storage tables, subscription and renewal ownership, immutable
publication provenance and the same commerce-first transaction units. Native
tables have RLS enabled and revoke PUBLIC and ordinary-role writes; the service
role has only the two client census column reads. Owner transaction stores carry
authority, which a managed twin can express with RLS and its service role. No
native-only authorization role or column relaxation is required. The managed
rail does not supply this feature.
