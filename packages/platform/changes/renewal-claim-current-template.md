- Fixed a billing defect in the node-postgres renewal rail. In Platform 1.3.x, a v1 renewal snapshot built before an accepted bundle edit and first claimed after it could charge the pre-edit amount. With the forward installed, version evidence that proves the snapshot stale causes a first claim to return `subscription_renewal_snapshot_stale`. On the retained v2 rail, a first claim with a mismatched snapshot fingerprint returns `subscription_renewal_snapshot_fingerprint_mismatch`. A first billing claim carrying `frozenRevision` or `templateSnapshot` must carry a usable positive integer in `templateSnapshot.version`. Unusable version evidence returns `subscription_renewal_claim_invalid_snapshot`. Bare legacy claims without build-version evidence are admitted as before.
