### Verified payments, truth and reconciliation

Contribute the payment truth, first-receipt ingress, method lifecycle, reconciliation and framework-free conformance runtime. The new internal evidence projection preserves raw verification bytes and maps adapter evidence into the donor carrier. Persistence and provider translation remain host-owned.

Migration: Before, missing refund evidence could apply a full refund. Now `require-evidence` refuses missing/null kind, amount or operation identity before terminal apply: the event is still durably recorded and acknowledged, but it is not applied. Hosts supply original payment money and stable operation identity with a cumulative snapshot, event delta, or explicit full-reversal observation (`refund` or `chargeback`). Explicit full evidence remains valid. Hosts needing the former default must explicitly select `refundEvidencePolicy: "legacy-assume-full"`; the reference handler accepts the same policy. No automatic host rewiring or native-store parity is included.
